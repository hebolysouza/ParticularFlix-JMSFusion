JMSFusion 4.0.0.12 for Jellyfin 12 (ParticularFlix fork). Layout settings saved per user, an explicit and protected global default, a mobile header fix for real phones and Home Screen Sections homes for new users without a restart. Same plugin GUID, settings are kept.

## 📦 Install

- Catalog URL: `https://raw.githubusercontent.com/hebolysouza/ParticularFlix-JMSFusion/main/manifest.json`
- Or manual: put the three files of `JMSFusion-4.0.0.12-server.zip` (DLL, `meta.json`, `icon.png`) in the plugin folder and restart Jellyfin.
- Requires Jellyfin 12.x (targetAbi 12.0.0.0, net10.0). Validated on 12.3. Jellyfin 10.11.x: stay on 3.8.2.45.

## ⬆️ Upgrade notes

- **Reload every open tab after updating.** The server now refuses settings saves from pages that did not load the server state, which includes pages still running the previous version.
- **Save/Apply no longer publishes the global default**, even with "Force global user settings" on. To change the default for everyone, use "Publish as default for everyone" in the JMS settings (administrators only) or the button of the plugin page.
- The mobile header fix lives in `extras/particularflix-modern-header.js`. On Jellyfin 12 it runs from the JMS `custom` folder (`<config>/data/plugins/configurations/JMSFusion/custom/`), not from the DLL: copy the new file there.
- Home Screen Sections model home is off until a model user is chosen on the plugin page.

## 🛠️ Fixes

- **The global default layout was overwritten without anyone publishing it.** With forced global settings, three paths of the administrator's browser wrote over the snapshot every user receives: Save/Apply (and the theme button) sent the settings object of the page, about 470 keys, over a default of about 610, dropping positions, layout tuning and similar keys; a page that could not read the server state (for example during a restart) seeded the server with its own, possibly outdated, local copy, with no click; and the "Publish admin settings globally" button sent the whole local storage of that site address. Now Save/Apply and the automatic save store only the signed-in user's own snapshot; with forced settings the administrator reads and edits their own snapshot and regular users keep receiving the default.
- **Mobile header on real phones.** Below 900 px Jellyfin 12 draws no navigation pills and the script stopped before the mobile header: phones kept SyncPlay and Cast in the bar and had no More button. It now runs with or without the pills. The Search button (`#/search?` in 12.3) is kept in the bar.
- **Home Screen Sections home refreshed after watching.** Marking a title played or unplayed, or finishing it, clears that user's cached home, so "Because you watched" and "Continue watching" update on the next home load instead of up to an hour later.

## ✨ New

- **Explicit global default**: "Publish as default for everyone" publishes the administrator's layout already saved on the server, after a confirmation that shows the key count of the current default and of the new one. "Undo last default publication" restores the previous default.
- **Protection against regressions**: a save or publication that drops more than 10% of the keys of a snapshot is refused unless asked for explicitly (Reset, or a second confirmation).
- **Audit trail**: every default publication, undo and refused save goes to the Jellyfin log and to a list of the last 100 events (time, user, address, origin, IP, browser, keys before and after), available to administrators at `/Plugins/JMSFusion/UserSettings/Audit`.
- **Home Screen Sections model home**: choose a model user on the plugin page; users without their own section list (new accounts, or older ones that never changed it) get a copy of the model's home within a minute, without restarting Jellyfin. Buttons copy the model home to users without their own or to everyone. API for administrators and API keys at `/Plugins/JMSFusion/HomeSections`.

## ⚠️ Known limitations

- The Home Screen Sections integration uses that plugin's public manager by reflection (no build dependency). If a future Home Screen Sections release changes it, the model home simply stops being applied; nothing else is affected.
- The mobile header applies to web and web-wrapper clients only (native TV apps do not run the plugin scripts).
- The C# changes of this release were built and validated on the owner's test and production servers; there is no automated test suite.
